Machine learning in FIE

How we use an SVM and feature extraction to predict whether a Chrome extension is benign or malicious.

Overview

After an extension is downloaded and unpacked, we analyze its manifest, HTML, CSS, and JavaScript to extract a fixed set of features. Those features are turned into a numeric vector and fed into a trained Support Vector Machine (SVM). The model outputs a probability that the extension is malicious; we then convert that into a risk score, risk level, and a recommended action.

Extension analysis

We scan the extension’s files and build a feature set that captures security-relevant behavior:

  • Manifest: Permissions, host permissions, and content security policy (CSP).
  • HTML: Counts of iframes, forms, scripts, inline event handlers, password inputs, meta refresh, external URLs, and other XSS- or phishing-related patterns.
  • CSS: Background-image usage, behavior and @import rules, and external url() references.
  • JavaScript: Obfuscation signals (whitespace %, average line length, specific characters, word size, string entropy), dynamic code generation (e.g. eval, setTimeout with string), DOM sinks, event handlers, HTTP/HTTPS script loading, webRequest modification callbacks, and XMLHttpRequest usage.

Feature vectorization

All of the above are merged into a single feature dictionary: permissions (as binary or counts), JS features, CSS features, and HTML features. The extension name is not used as a model input. This dictionary is converted into a fixed-length numeric vector that matches the columns the SVM was trained on; any missing features are filled with zero.

Model and prediction

We use a pre-trained SVM bundle (model, feature columns, and threshold). The model predicts the probability that the extension is malicious. If this probability is at or above the threshold, we label the extension MALICIOUS; otherwise we label it BENIGN. The same probability is used to compute a risk score (0–100), confidence (based on distance from the threshold), and a recommended action.

Risk score and levels

The risk score is derived from the model’s probability and the threshold: below the threshold, the score scales in 0–49; above it, 50–100. We then map the score to a risk level (e.g. LOW, MEDIUM, HIGH, CRITICAL) and to a recommended action such as “Allow,” “Review permissions & network access,” “Warn user / require review,” or “Block / quarantine.”

Why this helps

Malicious extensions often differ from benign ones in measurable ways: more sensitive permissions, obfuscated or packed JavaScript, risky DOM or network usage, and loading remote scripts. By turning these into numeric features and training an SVM on labeled data, we can automatically flag extensions that look like known malware while keeping the scanner fast and interpretable through the risk score and per-feature breakdowns in the other tabs.
